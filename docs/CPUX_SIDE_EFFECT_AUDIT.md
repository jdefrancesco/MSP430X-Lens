# CPUX Side-Effect Audit

Source: `docs/MSP430_APIGUIDE.pdf`, Section 6 "CPUX" (`SLAU208Q`, pages 186-341 in the PDF viewer).

This is a working checklist for the Binary Ninja MSP430X architecture plugin. It summarizes architectural side effects needed by the implemented lifter subset without copying the full manual text.

## Global CPUX Rules

- PC is 20-bit, word-aligned, and can branch/call throughout 1 MB only through 20-bit forms such as `MOVA ... ,PC`, `BRA`, `CALLA`, and `RETA`.
- `CALL`/`BR`/`RET` are lower-64KB forms; `CALLA`/`RETA` preserve the full 20-bit return address.
- Byte writes to CPU registers clear destination bits 19:8.
- Word writes to CPU registers clear destination bits 19:16.
- Address-word writes preserve/write bits 19:0.
- `SXT`/`SXTX` are register-write exceptions: the sign of bit 7 extends through bit 19. Register `SXT`/`SXTX` builds that 20-bit sign extension directly instead of masking a 32-bit sign extension afterward, and extension-word `SXT` displays as `SXTX`. Non-register `SXTX.A` uses the address-word memory helpers, including high-bank absolute operands, while non-register `SXTX.W` remains a word-width memory write.
- Extension-word `SWPB` displays as `SWPBX`; `.A` preserves bits 19:16 while swapping the low word bytes through the named `swpb20(value)` intrinsic, and `.W` writes a cleared-high-bits `swpbw(value)` word result. High-bank absolute memory operands preserve their extension-word address nibble in both text and LLIL.
- SR should be manipulated with `MOV`, `BIS`, and `BIC`; flag state must follow SR when SR is written or restored, and SR reads should reflect the current lifted flag values.
- Address-word memory operands are stored as two ascending words: low 16 bits first, high nibble in the next word.

## Implemented Instruction Side Effects

- `MOVA`: moves 20-bit values, does not affect flags, supports register, immediate, memory, indexed, indirect, autoincrement, absolute, and PC destinations implemented in the decoder.
- `CALLA`: treated as a 20-bit call; Binary Ninja LLIL `call` models call control flow. Register, indexed, indirect, autoincrement, absolute, symbolic, and immediate operand forms decode with 20-bit addresses. The hardware stack format is low word plus high nibble word for `RETA`.
- `RETA`: restores PC low word and PC high nibble from stack and returns; SR is not affected.
- `RETI`: restores SR plus PC high nibble from the first stack word, restores PC low word from the next stack word, syncs lifted flags from restored SR, then returns.
- `PUSHM.A`/`POPM.A`: push/pop n 20-bit registers, using 4 stack bytes per register; flags are unaffected except when SR is popped. The lifter uses native stack IL for these block save/restore forms so Binary Ninja can recognize callee-saved register prologues and avoid showing helper-backed local `store20`/`load20` noise.
- `PUSHM.W`/`POPM.W`: push/pop n 16-bit registers, using 2 stack bytes per register; popped register high bits are cleared; flags are unaffected except when SR is popped.
- Compact register shifts (`RRCM`, `RRAM`, `RLAM`, `RRUM`): decode the non-extension-word `.A`/`.W` forms with repeat counts 1-4. `.W` writes clear register bits 19:16; address-word `RLAM`, `RRAM`, and `RRUM` fold the repeat count into one shift plus final flag canonicalization to avoid repeated `& 0xfffff` chains. Address-width `RLAM` keeps the normal shifted value unmasked in data flow and derives flags from source bits, which avoids noisy pointer-index expressions such as masked-left-shift-masked chains. Address-width arithmetic right shifts use a named `sra20(value, count)` intrinsic to represent 20-bit sign-fill without expanding into manual mask algebra. The common compiler idiom `RLAM.A #4, Rn; RRAM.A #4, Rn` now decodes as the local pseudo `sext20.w Rn` and lifts through `sext20w(value)`, keeping word-to-20-bit signed table indexes compact in HLIL. The firmware's signed scale-by-six table-index idiom `MOVA Rs,Rd; RLAM.W #2,Rd; RLAM.W #1,Rs; ADD Rs,Rd; ADD #bias,Rd; sext20.w Rd` decodes as local pseudo `sxtidx6.w Rs,#bias,Rd`, preserves the doubled-source-register side effect, and lifts through `sxtidx6w(value,bias)` to avoid shift/add flag ladders in menu-string table loops. The unsigned 20-bit scale-by-six carry-chain table-index idiom ending in `BISX.A R15,R12` decodes as local pseudo `idx6.w R15,R12` only when followed by `ADDA #base,R12`; that following address add overwrites the core ladder flags, so the fold can keep the helper register side effects while avoiding the large carry-reconstruction expression in HLIL. Firmware-derived word-pair shift helpers that repeatedly propagate between `R13:R12` now decode as local pseudos `lsl32.w #n,R13:R12` and `lsr32.w #n,R13:R12`, lifting through named intrinsics so long left/right shift helpers do not decompile as carry-bit ladders. `RRCM` keeps per-step carry-chain modeling. `RRCM`, `RRAM`, and `RRUM` clear V, while `RLAM` leaves V undefined/unassigned.
- Extension-word right shifts (`RRCX`, `RRAX`, `RRUX`): decode register and non-register forms with `.A`, `.W`, and `.B` names, including indexed, absolute, indirect, and autoincrement operands. High-bank non-register operands preserve extension-word address nibbles without inventing repeat prefixes, while true immediate/register repeats still display and lift as repeats. Immediate `RPT #n` prefixes on non-autoincrement shifts are folded while still shown in disassembly; repeated register and stable memory forms use named `rpt_rrcx*`, `rpt_rrax*`, and `rpt_rrux*` intrinsics instead of dynamic loop IL. Repeated autoincrement memory forms reload, advance the pointer, and write back through the saved original address each iteration. Address-width `RRAX` uses the named `sra20(value, count)` intrinsic rather than shift-up/shift-down sign-extension ladders or manual sign-fill masks after folded repeats. Word/byte `RRAX` uses native signed shifts, including immediate repeats, to avoid manual sign-fill ladders in HLIL. `.A` shifts use bit 19 as the carry/sign insertion boundary rather than bit 31; C receives the outgoing LSB; N/Z reflect the final result; V is reset.
- Immediate `RPT #n` on register-register double-operand CPUX instructions is folded for arithmetic and logical operations, including carry-chain operations (`ADDC`, `SUBC`, and `DADD`). Fixed-count self-add idioms such as `RPT #16; ADDX.A Rn,Rn` lift through `rpt_selfadd*` intrinsics instead of unrolled doubling ladders. Register-count `RPT Rn` on supported double-operand repeats lifts as a dynamic loop. Final flags come from the last folded or looped iteration, and `DADD` still leaves V undefined/unassigned.
- Immediate `RPT #n` on double-operand CPUX instructions with an autoincrement source and register destination, such as `ADDX.A @SP+,Rn`, is folded so each iteration reloads the source and advances the source register by the active operand width. Memory destinations are treated as extension-word address destinations rather than repeat forms.
- Extension-word Format I double-operand instructions display with `X` mnemonics (`MOVX`, `ADDX`, `CMPX`, `DADDX`, and peers) and use extension-word high nibbles for 20-bit immediates, absolute operands, symbolic operands, and indexed source/destination offsets.
- Arithmetic and compare (`ADD`, `ADDC`, `SUB`, `SUBC`, `CMP`, `ADDA`, `SUBA`, `CMPA`) update N/Z/C/V according to the operand width. Immediate address-width arithmetic sources skip redundant source mask temps because extension-word immediate decoding already confines them to the active width. Address-width add/sub/compare flags derive N/Z/C/V from canonical operands and the full arithmetic expression instead of materializing a separate masked result temp. Flag-setting double-operand writes emit flags before the destination write when the flag expression depends on the old destination, so HLIL does not re-read a just-written register while reconstructing table indexes or address arithmetic.
- Logical flag-setting operations (`AND`, `BIT`) update N/Z/C and clear V; immediate address-width logical masks skip redundant result mask temps because the immediate already confines the result to the active width. `XOR` updates N/Z/C and sets V when both original operands are negative. Address-width `XOR` flag lifting uses direct sign-bit tests for V, avoiding full operand mask temps.
- `XOR #-1,dst` lifts as an explicit invert operation with equivalent XOR flags, avoiding `0xffff` constants that Binary Ninja may render as interrupt-vector symbols.
- `BIC`, `BIS`, `MOV`, `MOVA`, `SWPB`/`SWPBX`, `PUSH`, `CALL`, `CALLA`, `RETA`, and `PUSHM` do not directly affect flags, except SR writes/restores are reflected in lifted flags.
- Status-register reads reconstruct the tracked C/Z/N/V bits from Binary Ninja flags, but normal flag-setting operations do not rewrite the `sr` register after each flag assignment. This keeps HLIL from growing repeated `sr & ...` chains while preserving explicit SR read/write behavior.
- `DADD`/`DADDX`: compute BCD result and N/Z/C through named `daddb`, `daddw`, and `dadd20` intrinsics that return result plus carry. V is undefined by the architecture and is intentionally not assigned. The intrinsic model keeps repeated decimal-adjust digit ladders out of LLIL/HLIL while preserving the visible carry side effect.

## Known Gaps

These are ordered by the amount of decompiler noise or semantic risk they are likely to cause. Each item should grow one or more BN-backed regression tests before being marked implemented.

### P0: Extension-Word Repeat Semantics

- Current behavior: immediate `RPT #n` prefixes are decoded for supported extension-word forms. `RRCX`, `RRAX`, and `RRUX` register and non-autoincrement memory forms fold immediate repeats; `.A` `RRAX`/`RRUX` avoid per-bit mask chains when the final result and carry can be derived directly. Double-operand `RPT` is recorded only for register destinations, matching assembler-accepted forms and avoiding confusion between extension-word repeat bits and high-bank destination address bits. Immediate-count stable register `ADD`/`ADDA`, fixed-count self-add `ADD`/`ADDA`, `ADDC`, `SUB`/`SUBA`, `SUBC`, `DADD`, and register `XOR` repeats fold through compact result/carry intrinsics instead of unrolled IL. Immediate-count idempotent register/immediate repeats (`MOV`/`MOVA`, `BIT`, `BIC`, `BIS`, `CMP`/`CMPA`, and `AND`) fold to one visible operation when no memory, PC, or status-register side effects are involved. Register-count non-autoincrement `ADD`/`ADDA`, `ADDC`, `SUB`/`SUBA`, `SUBC`, and `DADD` repeats lift through compact result/carry intrinsics (plus overflow where the instruction defines it), while self-updating register arithmetic and autoincrement forms stay looped. Register-count stable-source `XOR` repeats with normal register destinations lift through compact result/carry/overflow intrinsics; self-aliasing and memory-source forms stay looped because repeated XOR is count-parity sensitive. Register-count word and byte arithmetic/logical repeat results write back through zero-extension, preserving MSP430X high-bit clearing semantics. Register-count idempotent register/immediate repeats fold to one visible operation under the same no-memory/no-PC/no-SR rule; memory-sourced forms stay looped.
- Required behavior: model `RPT #n` and `RPT Rn` for the following instruction. For readability, prefer folding small immediate repeats into the lifted operation when practical, and preserve an explicit repeat marker in disassembly when folding would hide control-relevant behavior.
- Side effects to preserve: repeated arithmetic/logical instructions must update flags as if the instruction executed repeatedly, with the final iteration's flags visible. Repeated autoincrement sources must reload and advance each iteration for register destinations.
- Regression targets: add more concrete firmware-derived repeat combinations as they appear, especially carry-chain operations; current tests include immediate-count stable register arithmetic/carry/decimal/logical folds, register-destination autoincrement-source repeats, register-count word/byte `ADD`, `ADDC`, `SUBC`, `DADD`, and `XOR` register writes, and negative tests proving high-bank memory destinations are not decoded as repeats.

### P0: Extension-Word Rotate/Shift Forms

- Current behavior: register, indexed, absolute, indirect, and autoincrement forms for `RRAX`, `RRCX`, and `RRUX` decode and lift with `.A`, `.W`, and `.B` widths. Immediate repeat prefixes are folded for non-autoincrement operands; immediate-count non-autoincrement `RRCX` and register-count non-autoincrement repeats lift through named result/carry intrinsics (`rpt_rrcx*`, `rpt_rrax*`, `rpt_rrux*`) across address, word, and byte widths to avoid dynamic-loop noise, and repeated autoincrement forms reload and write back through the saved original address each iteration.
- Required behavior: decode/text/lift `RRAX`, `RRCX`, and `RRUX` with `.A`, `.W`, and `.B` widths, including non-register destination forms where the manual permits them.
- Side effects to preserve: `.A` uses bit 19 as the sign/carry insertion boundary, `.W` clears destination bits 19:16, `.B` clears destination bits 19:8 for register destinations, `RRAX` sign-extends through the active width, `RRCX` inserts carry into the active MSB, `RRUX` inserts zero, C receives the outgoing LSB, N/Z reflect the final result, and V is reset.
- Regression targets: add more concrete firmware-derived `.A` value-flow cases as they appear; current tests cover compact `RRAM.A`, repeated `RRAX.A` sign-fill using bit 19 while avoiding 32-bit sign-fill artifacts, immediate-count `RRCX` named-intrinsic lifting for register and memory destinations, and register-count `RRCX`/`RRAX`/`RRUX` named-intrinsic lifting across `.A`, `.W`, and `.B` register and stable memory destinations.

### P1: Full `MOVX`/`ADDX`/`CMPX`/`DADDX` Operand Coverage

- Current behavior: extension-word Format I instructions display with `X` mnemonics and preserve 20-bit high nibbles for immediate, absolute, symbolic, indexed source, and indexed destination operands in both text and LLIL address expressions. Signed 20-bit indexed displacements display as signed offsets; symbolic PC-relative displacements resolve to absolute addresses. High-bank `.W`/`.B` memory sources use the active memory width and still clear high register bits on writes. High-bank register-source memory destinations across the Format I arithmetic/logical family lift once as normal memory operations rather than fake `RPT` forms. PC destinations preserve direct branch info for immediate sources and indirect branch/jump behavior for memory/indexed sources. `.W` and `.B` `DADDX` immediates lift through compact BCD intrinsics instead of expanded digit ladders.
- Required behavior: preserve and display the CPUX `X` mnemonic family where it improves clarity (`movx.a`, `addx.a`, `cmpx.a`, `daddx.a`) and use extension-word high nibbles for 20-bit source and destination indexes, symbolic addresses, absolute addresses, and immediates.
- Side effects to preserve: byte and word writes to registers clear high bits as described in the global rules, address-word operations preserve bits 19:0, arithmetic/compare flags match the active width, `DADDX` leaves V undefined, and PC destinations produce branch/control-flow information.
- Regression targets: add more concrete firmware-derived operand combinations when encountered; current tests cover `MOVX.A #imm,PC`, `MOVX.A X(Rn),PC`, high-bank `MOVX`/`ADDX`/`ADDCX`/`SUBCX`/`SUBX`/`CMPX`/`DADDX`/`BITX`/`BICX`/`BISX`/`XORX`/`ANDX` absolute/indexed memory destinations with register sources, `ADDX.A`/`CMPX.A`/`DADDX.A` indexed memory source-destination pairs, negative 20-bit indexed offsets, and negative symbolic PC-relative operands.

### P1: `PUSHX`/`POPX` Single-Operand Stack Forms

- Current behavior: core `PUSH`, `PUSHX.A/.W/.B`, `POPX.A/.W/.B` emulation through `MOVX @SP+,dst`, and compact `PUSHM`/`POPM` forms decode, display, and lift. `PUSHX.A` uses a four-byte stack slot; `PUSHX.W/.B` use one stack word. Register `PUSHX.A/.W`, register `POPX.A/.W`, and `PUSHM`/`POPM` use native stack push/pop IL for cleaner save/restore recovery in HLIL; byte and memory forms keep explicit stack memory modeling, including helper-backed `.A` memory `PUSHX` loads and `POPX` stores. High-bank absolute and indexed `.A` `POPX` memory destinations preserve the extension-word destination high nibble instead of being mistaken for immediate `RPT` prefixes. `POPX.W SR` restores the status flags through the normal SR write path.
- Required behavior: decode/text/lift `PUSHX.A`, `PUSHX.W`, `PUSHX.B`, and `POPX` emulation (`MOVX @SP+,dst`) with the expected MSP430X stack widths.
- Side effects to preserve: `.A` stack values occupy two words with only bits 19:0 meaningful, `.W` stack values occupy one word and clear destination bits 19:16 on register pop, `.B` clears destination bits 19:8 on register pop, and status flags are unaffected except when SR is restored.
- Regression targets: add byte-exact stack layout tests if `load20`/`store20` helper semantics ever move behind a selectable byte-exact mode.

### P2: Address-Word Memory Helper Modeling

- Current behavior: address-word memory loads/stores are represented with local `load20(addr)` and `store20(addr,value)` LLIL intrinsics. This keeps decompilation readable while making the 20-bit two-word layout explicit instead of pretending `.A` memory operands are native 32-bit slots.
- Required behavior: keep using helper intrinsics for address-word memory unless a byte-exact mode is added later. The architecture stores low 16 bits at `addr` and the high nibble in the next word at `addr + 2`, so helpers should remain shared by address tables, memory `MOVA`, indirect `CALLA`/`BRA`, indexed `BRA` jump tables with 20-bit table bases, `.A` stack values, and repeated address-word memory operations.
- Side effects to preserve: address tables, `MOVA` memory operands, `CALLA`/`BRA` through memory, and `.A` stack values must agree about the two-word layout.
- Regression targets: add additional address-word memory round trips as concrete firmware patterns appear. Current tests cover helper-backed `.A` stack widths and register order for `PUSHX.A`, `POPX.A`, `PUSHM.A`, and `POPM.A`, plus 2-byte `.W` stack widths. `MOVA` coverage now includes helper-backed address-word memory loads from `@Rn`, `@Rn+`, `&addr`, and indexed operands, plus stores to absolute and indexed operands. `BRA &addr`, `CALLA &addr`, and indexed branch tables verify branch/control-flow behavior through `load20`, including jump tables stored above the lower 64K. Readability tests verify the helpers do not reintroduce 20-bit mask noise. `RETA` coverage verifies the byte-exact two-word stack pop layout, high-nibble PC reconstruction, return control flow, and no SR/flag side effects.

### P2: Disassembly Naming And Pseudo-Instruction Cleanup

- Current behavior: lower-64KB PC destinations display as `BR` instead of the underlying `MOV ...,PC`, address-word PC destinations display as `BRA` instead of the underlying `MOVA`/`MOVX.A ...,PC`, classic `MOV @SP+,PC` displays as `RET`, classic `MOVA @SP+,PC` and extension-word `MOVX.A @SP+,PC` display as `RETA`, and `MOVX @SP+,dst` displays as `POPX` for register, absolute, and indexed destinations. Extension-word Format I instructions display with `X` mnemonics where the extension word changes width or operands.
- Required behavior: prefer CPUX names when they reduce ambiguity: `BR` for lower-64KB `MOV src,PC`, `BRA` for `MOVA dst,PC`, `RET` for `MOV @SP+,PC`, `RETA` for `MOVA @SP+,PC`, `POPX` for `MOVX @SP+,dst`, and `X` mnemonics when an extension word changes address width or repeat behavior.
- Side effects to preserve: pseudo-name cleanup must not hide branches, returns, calls, or flag updates from Binary Ninja's analysis.
- Regression targets: expand alias coverage only when new TI pseudo-instructions are decoded; current tests cover `BR` immediate, register, indirect, and autoincrement PC destinations, `BRA` immediate, indirect, absolute, indexed, extension-word indexed PC destinations, `RET`, `RETA`, and `POPX.A/.W/.B`.
